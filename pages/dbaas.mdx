# DBaaS API

Liara's Database as a Service (DBaaS) API lets you create and run managed databases, back them up, and connect your apps to them.

## Overview

The DBaaS API enables you to:

- **Create and manage databases** - Create databases of several engines in your private networks
- **Scale resources** - Move databases to bigger plans and grow their disks
- **Manage backups** - Create backups on demand, download them, and create new databases from them
- **Monitor** - Read CPU, memory, disk and network usage, lifecycle events and the progress of background operations
- **Configure settings** - Change engine parameters for MySQL, MariaDB and PostgreSQL
- **Control network access** - Turn public network access on or off

## Supported Database Types

- **MySQL** and **MariaDB**
- **PostgreSQL**
- **MongoDB**
- **Redis**
- **SQL Server** (`mssql`)
- **Elasticsearch**
- **RabbitMQ**
- **ClickHouse**

## Key Features

### Private Networks

Databases are created in one of your private networks. Apps in the same network reach the database by its hostname, without exposing it to the internet.

### Plans

Each database has a resource plan and a bundle plan. The bundle plan sets backups, metrics retention, editable settings and public network access.

### Backup Management

- **Automated Backups**: Scheduled backups, depending on the bundle plan
- **Manual Backups**: Create a backup before major changes
- **Backup Downloads**: Download backups for local storage or migration
- **Restore**: Create a new database from a backup of another database of the same type

### Control Panel

Turn on a web control panel for MySQL, MariaDB, PostgreSQL, Redis, Elasticsearch and RabbitMQ databases.

### Public Network Control

Turn public network access on or off at any time, if your bundle plan allows it.

## Base URL

```
https://api.liara.ir
```

## Common Operations

### Creating a Database

When creating a database, specify:
- **hostname**: A unique name, also used as its hostname inside the network
- **type**: The database engine
- **version**: The engine version
- **planID** and **bundlePlanID**: The resource and bundle plans
- **network**: The private network to create it in
- **publicNetwork**: Whether to allow access from the internet

### Monitoring

Access metrics including:
- CPU usage over time
- Memory consumption
- Network receive/transmit statistics
- Disk usage

### Events

Read the database's lifecycle events, such as starts, stops and restarts, for troubleshooting.

## Getting Started

1. Create a network, or pick an existing one
2. Choose the database type, version and plans
3. Create the database using the API
4. Read the connection details from the get-database endpoint
5. Connect your application using the provided credentials

## Best Practices

- Keep databases private and connect from apps in the same network when possible
- Back up your database before making major changes
- Monitor resource usage to know when to move to a bigger plan
